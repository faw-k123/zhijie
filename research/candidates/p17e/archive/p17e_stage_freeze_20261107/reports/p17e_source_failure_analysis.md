# P17-E 来源请求失败分析

## 1. 为什么 19 个失败

40 个案例首要来源中：

```text
HTTP 200：20
HTTP 202：1
请求失败：19
```

19 个失败不是同一个原因：

| 原因 | 数量 | 案例 |
|---|---:|---|
| SSL/TLS 握手中断 | 12 | CASE002、006、011、016、018、019、020、022、023、024、027、029 |
| HTTP 502 网关错误 | 5 | CASE003、004、007、015、040 |
| HTTP 403 拒绝访问 | 2 | CASE013、021 |
| HTTP 202 挑战响应 | 1 | CASE025 |

### SSL 中断

`UNEXPECTED_EOF_WHILE_READING` 表示远端在 TLS 握手/响应阶段主动断开。  
常见原因：

- 站点要求浏览器/HTTP2；
- CDN 或 WAF 拦截脚本请求；
- 区域网络路径不稳定；
- 站点临时故障。

不能据此认定 URL 失效或案例不存在。

### 502

网关/上游服务器错误，通常是站点侧或 CDN 侧临时故障。  
需要稍后重试或改用官方档案页。

### 403

站点主动拒绝非浏览器请求，属于反爬/访问控制。  
需要人工浏览器访问或使用机构存档。

### 202

服务器接受了请求但返回挑战/排队响应，不是正常正文。  
不能把 202 当作内容已核验。

## 2. 为什么 CASE008 显示 200 但仍有 SSL 错误

首次脚本请求 CASE008 也遇到 SSL 中断；随后用浏览器/页面抓取成功，人工打开原文，确认活动与两首曲目演出。  
因此 CSV 中保留：

```text
http_status=200
content_verified=YES
error=SSL...
```

这是“首次失败、人工复核成功”的记录，不是矛盾。

## 3. 成功访问的 20 个来源

20 个 HTTP 200 中：

```text
仅检查 URL 可访问：19
逐页内容确认：1（CASE008）
```

URL 可访问不等于内容支持案例；不能把可访问写成已核实。

## 4. 重试策略

下一批按以下顺序处理失败来源：

1. 用浏览器/人工打开原始 URL；
2. 使用站点搜索或官方档案替代 URL；
3. 使用 Wayback/机构存档（如有）；
4. 记录“仍不可访问”，不伪造内容；
5. 对 502 类稍后重试，对 403 类不反复抓取。

## 5. 对结论的影响

```text
19 个来源不可脚本访问
→ 40 案例不能全部声称 verified
→ 只能部分核实
→ 不能进入正式证据合并
```
