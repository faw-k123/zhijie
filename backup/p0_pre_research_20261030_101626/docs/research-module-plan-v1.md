## 0. 结论先行

1. **不新建数据库表、不做数据库迁移。** 研究数据先以版本化 JSON 为唯一数据源，后端只读加载、校验、统计；后续案例扩充时替换 JSON 即可，避免 SQL Server 环境不稳定影响答辩。
2. **保留三张主页面，但只保留“壳”，内容全部重做：**
   - 全球传播效果页：从“评论球 + 原始 JSON”改为“全球传播驾驶舱”。
   - 音乐详情页：保留原有三个 Tab，新增第四个“海外传播”Tab。
   - 宣传方案页：从“四个输入框 + 一段文案”改为“区域传播方案生成器”。
3. **新增三张研究支撑页：** 案例库、案例详情、研究洞察（成功机制 / 音乐潜力 / 区域矩阵）。否则老师的五类成果在程序里没有落点。
4. **先接 3 个真实案例，页面如实显示“3 / 40”。** 不补假数据、不伪造排名；数据不足时显示“证据不足”，而不是用 0 分或占位数字冒充。
5. **视觉不照搬参考图的白底蓝调。** 参考图只取信息架构、图表和卡片组织方式；颜色统一到现有站点的墨绿 / 青玉 / 米金体系，避免全站割裂。
6. **把“北京 / 上海”作为城市外宣维度纳入，而不是另做两个孤立页面。** 方案页增加“作品来源城市/文化原点”，区域矩阵增加“北京 / 上海 / 不限”筛选；生成结果增加“城市外宣落点”，避免老师要求的城市维度在系统里丢失。

## 3. 页面级详细方案

### 3.1 全球传播效果页（改造）

**目标：** 一屏看懂“案例从哪来、哪些因素反复出现、哪些国家/乐器值得优先看”，而不是堆原始分析文本。

**结构：**

```
┌ 全球传播效果   [已核验 3 / 目标 40] [最近更新 2026-10-25] ┐
│ 副标题：基于已核验外国演奏案例的传播机制与区域适配分析      │
│ [查看案例库] [生成区域方案]                                │
├ KPI：案例数 / 覆盖国家 / 乐器数 / 平均有效编码 / A·B 证据率 ┤
├ 筛选：区域 国家 乐器 渠道 时代主题 证据等级 [重置]         ┤
│ ┌────────────── 世界地图 60% ─────────────┐ ┌ 右栏 40% ┐ │
│ │ 点阵世界地图 + 国家光点 + 弧线            │ │ 成功因素 │ │
│ │ 点大小=案例数，颜色=平均编码              │ │ TOP 6    │ │
│ │ 点击国家=筛选                             │ │ 样本提示 │ │
│ └──────────────────────────────────────────┘ └──────────┘ │
├ 代表案例（3 张卡）                              [全部案例] ┤
├ 受众原声（有数据才显示，保留现有评论能力）                 ┤
├ 音乐潜力 Top 5 预览（有 05 数据才显示）                    ┤
└ 城市外宣入口：[北京] [上海] [不限] → 带筛选进入研究洞察/方案页 ┘
```

**具体步骤：**

1. 删除现有评论球和无意义的 `<pre>` 面板；评论区改为底部“受众原声”证据条，最多 3 条，标注来源。
2. 顶部 KPI 全部来自 `/api/research/overview/`，不允许前端硬编码。
3. 世界地图用 ECharts `geo` + 本地简化 GeoJSON，不做真 3D 地球；用光点、同心圆、弧线模拟参考图的科技感，保证可点击、可测试、离线可用。
4. 右栏成功因素取 10 项指标中有有效评分的项，按均值排序；每项显示 `均值 / 3` 与 `n=有效案例数`。
5. 样本少于 5 例时，右栏固定显示提示：“当前为小样本频次描述，不构成普遍规律，也不代表某国受众整体偏好。”
6. 点击国家点、案例卡、成功因素都能联动筛选或跳转。
7. 空状态：没有案例时显示“案例库尚未导入”，并给出文件路径，不显示 0 值图表。

**验收：** 3 个案例能在图上定位到法国、美国、日本；筛选法国后只剩 CASE001；刷新不出现 `placeholder` 字样。

### 3.2 案例库页（新增）

**目标：** 把 40 个案例变成可检索、可核验的研究资产，而不是散落的 Word。

**结构：**

```
案例库
[搜索演奏者/曲目/乐器/国家] [区域] [乐器] [渠道] [等级] [列表/卡片]
已入库 3 / 目标 40    [x] 仅显示 A/B 证据等级   [ ] 显示待核实
┌ 缩略图 ┬ 案例标题 / 演奏者 / 国家 / 乐器 / 年份
│        │ 编码均分 2.6/3 · 证据 B · 来源 3 条 · 标签
│        │ [查看详情] [以此生成方案]
└────────┴────────────────────────────────────────────
分页 12 / 页
```

**具体步骤：**

1. 顶部显示完成度，不把“3”说成“40”。
2. 默认只显示 A/B；C/D 需要手动打开，避免未核实数据进入展示。
3. 筛选条件与 URL query 同步，便于从全球页带条件跳转。
4. 列表项包含：缩略图、CASE 编号、演奏者/机构、国家、乐器、年份、渠道、编码均分、证据等级、来源数。
5. 缩略图优先用案例截图，缺失时回退到现有乐器海报（`frontend/src/assets/images/poster/乐器/`）。
6. 无结果时显示“没有符合筛选的案例”，并提供清空筛选。
7. 分页在后端做，前端不一次拉全量。

**验收：** 搜索“二胡”出现 CASE001、CASE003；切到“仅 A/B”时 C/D 不出现；翻页不重复、不丢筛选。

### 3.3 案例详情页（新增）

**目标：** 让老师能从一个案例直接看到“证据链”，而不是只看结论。

**结构：**

```
← 返回案例库
[封面] CASE001 / Eliott Tordo / 法国 / 二胡 / 证据 B
01 案例摘要（谁、何时、在哪里、做了什么、为什么值得研究）
02 成功要素（10 项横向评分条，每项下面一行证据说明）
03 传播链（学习动机 → 内容发布 → 媒体报道 → 巡演/教学）
04 证据与来源（来源编号、标题、机构、日期、链接、访问日期）
05 相关曲目 / 相似案例
[以此案例生成区域方案]
```

**具体步骤：**

1. 详情数据来自 `/api/research/cases/<case_id>/`。
2. 10 项评分逐项显示分数与证据，未知项显示“未知”，不画成 0。
3. 来源链接 `target="_blank"` + `rel="noopener noreferrer"`，并显示“截至日期”。
4. 页面明确区分“原始证据”和“研究者判断”，判断性文字前加“分析：”。
5. C/D 级案例在顶部显示黄色警示条：“该案例尚未完成复核，不作为正式结论依据。”
6. 底部放 3 个相似案例，点击可跳转。
7. 404 时显示“案例不存在或未公开”，不白屏。

**验收：** CASE001 的 3 条来源可打开；未知指标不显示 0；相似案例不包含自己。

### 3.4 音乐详情页“海外传播”Tab（改造）

**目标：** 用户选一首歌后，能直接看到“这首歌为什么可能被海外接受、适合哪里、有什么风险、有哪些先例”。

**结构：**

```
基础 | 情感分析 | 国际传播分析 | 海外传播（新）
┌ 传播潜力 XX/100 · 等级 ┐ ┌ 评分依据 / 数据状态 ┐
├ 相似海外案例（2—4 个）      ├ 适合区域（chips）    ┤
├ 文化兴趣点（音色/故事/意象）  ├ 文化适配建议         ┤
├ 推荐时代主题（chips）        ├ 文化风险提示         ┤
└ [以此生成区域方案] ──────────┴ 证据来源 ───────────┘
```

**具体步骤：**

1. `tab` 类型从 `'basic' | 'emotion' | 'report'` 扩为四值；只加分支，不改原三个分支。
2. 切歌或首次进入 Tab 时调用 `/api/research/music-context/`，按 `song_id` 缓存，避免重复请求。
3. 潜力总分和等级由后端按 8 项权重计算；前端只展示，不重算。
4. 相似案例按“乐器、音乐类型、主题、区域、渠道”召回，显示匹配理由。
5. “文化兴趣点”不只写“文化底蕴深厚”，要落到可感知的钩子：音色、历史故事、山水/自然意象、节庆/服饰、演奏技法、影视/游戏关联；每一项尽量挂来源。
6. 没有评分时显示“该曲尚未进入 20 首候选清单”，并推荐同乐器案例，不伪造分数。
7. “生成区域方案”按钮带 `song/title/category/subcategory` 参数跳转 `/promo-report`。
8. 原有音频、评论、词云、情感分析逻辑保持不动；新增请求失败不能影响原三 Tab。

**验收：** 打开任一歌曲，原三 Tab 正常；第四个 Tab 有加载态、空态、错误态；跳转方案页时歌曲已预选。

### 3.5 研究洞察页（新增）

**目标：** 把老师的“成功机制、20 首潜力排名、区域—文化—宗教—时代主题矩阵”三块成果集中展示。

**路由：** `/research-insights?tab=mechanism|potential|matrix`

#### Tab A：成功机制

- 10 项成功因素总排行（均值、有效样本数、代表案例编号）。
- 区域 × 成功因素热力图；样本不足的格子显示“样本不足”，不填 0。
- 6—8 个代表案例卡：个人、学校、合作演出、网络传播、反例各至少 1 个（数据够时）。
- 每条结论采用“在 N 个案例中，有 M 个……”的句式，并附案例编号。
- 页面固定显示“频次描述，不做显著性推断”。

#### Tab B：音乐潜力

- 20 首候选曲目表：曲名、类别、乐器、8 项分、加权总分、等级。
- 等级：80—100 优先传播；65—79 适合传播但需适配；50—64 需较多解释；50 以下暂不主推。
- 点击展开：为什么推荐、参考案例、适合区域、建议主题、改编建议、误读风险。
- 8 项权重必须与老师要求完全一致：情感共通性 20%、音色辨识度 15%、旋律易接受度 15%、文化故事可解释性 10%、跨文化改编空间 10%、视觉表现力 10%、时代主题关联度 10%、已有案例或海外反馈 10%。
- 任一项缺失时不做总分排名，标“资料不足”，不用 0 补齐。

#### Tab C：区域矩阵

- 6 个区域：东亚、东南亚、欧洲、北美、中东及部分伊斯兰文化地区、拉丁美洲。
- 增加“城市外宣”筛选：北京 / 上海 / 不限；北京、上海只作为“文化原点/作品来源城市”，不替代目标国家。
- 每个区域再分受众：音乐学院、华裔社群、青年短视频用户、世界音乐爱好者、博物馆/文化机构等。
- 每个“音乐 × 区域”组合展示：目标国家、语言、文化背景、宗教习俗注意事项、推荐音乐、时代主题、平台、形式、参考案例、改编建议、风险、来源。
- 北京/上海组合额外展示：城市文化锚点、可用的城市场景（中轴线、胡同、江南水乡、海派建筑等，须有来源）、城市外宣叙事、可复用案例。没有来源的城市标签不进入正式推荐。
- 所有宗教/文化描述必须带来源；没有来源的字段显示“待补来源”，不允许凭印象填写。
- 一键“用这个组合生成方案”跳转 `/promo-report` 并预填。

**验收：** 三个 Tab 可深链接；无数据时显示对应 CSV 路径和“待导入”，不显示假图。

### 3.6 区域传播方案页（改造）

**目标：** 从“写一段宣传文案”升级为“有案例依据的完整区域传播方案”。

**布局：** 左侧参数区（可折叠/粘性），右侧结果区。

**左侧字段：**

1. 音乐：大类 → 小类 → 曲目（支持 URL 预选）。
2. 目标区域：6 选 1。
3. 目标国家/地区：随区域联动。
4. 目标受众：音乐学院学生 / 华裔社群 / 青年短视频用户 / 世界音乐爱好者 / 博物馆与文化机构 / 综合。
5. 文化圈层（可选，沿用现有 testOverrides 选项）。
6. 时代主题：丝绸之路与文明交流、和平与友谊、自然生态与山水审美、乡愁与迁徙、非遗保护、青年文化交流、女性艺术表达、城市化与传统记忆、数字技术与传统音乐、心理疗愈与情绪共鸣。
7. 宗教/文化注意事项：根据区域自动带出，可编辑。

## 4. 后端与 API 设计

### 4.1 文件规划

```
backend/propagation/
├─ services.py                 # 保留旧接口；新增转发
├─ research_data.py            # JSON/CSV 加载、校验、缓存
├─ research_analytics.py       # 统计、相似案例、潜力计算
├─ plan_generator.py           # 检索 + 规则模板 + 可选 LLM
└─ data/
   ├─ foreign_cases.json
   ├─ case_success_factors.json
   ├─ music_propagation_scores.json
   ├─ regional_strategies.json
   └─ meta.json
```

不新增 Django app，不新增 migration。原因：研究数据是只读展示数据，JSON 足够；以后要后台录入再升级为模型。

### 4.2 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/research/overview/` | KPI、国家/乐器/渠道分布、成功因素、数据状态 |
| GET | `/api/research/cases/` | 案例列表；支持 `q/region/country/instrument/channel/theme/grade/page/page_size` |
| GET | `/api/research/cases/<case_id>/` | 案例详情、10 项评分与证据、来源、相似案例 |
| GET | `/api/research/music-context/` | 音乐详情页：`song_id/title/category/subcategory` |
| GET | `/api/research/music-potential/` | 20 首潜力榜与分项 |
| GET | `/api/research/regional-matrix/` | 区域矩阵；支持 `region/theme/audience/city` |
| POST | `/api/research/promo-plan/` | 结构化传播方案 |

统一响应：

```json
{
  "success": true,
  "data": {},
  "message": ""
}
```

### 4.3 关键实现点

1. **数据仓库**：启动时或首次请求加载 JSON，按文件 mtime 缓存；字段缺失时返回可读错误，不让页面白屏。
2. **只读 + 审核门**：`review_status` 为 C/D 或 `display_allowed=false` 的案例默认不进入统计和推荐。
3. **统计口径**：所有均值同时返回 `n`；`n=0` 返回 `null`，不返回 0。
4. **相似案例**：规则打分（乐器 30、音乐类型 15、主题 15、区域/国家 15、渠道 10、文本重叠 15），返回匹配理由，不只返回 ID。
5. **潜力计算**：后端按 8 项权重计算，前端只展示；缺项时不排名。
6. **方案生成**：先检索 2—4 个案例，再填模板；LLM 可选。LLM 不可用、超时、返回格式错误时，直接返回模板方案，`generation_mode='template'`。
7. **防编造**：方案中的案例编号必须来自检索结果；数字必须来自数据仓库；不满足就删掉或降级为“待补充”。
8. **兼容旧接口**：`/api/global/propagation/` 和 `/api/promo/report/` 保留，但新页面不再调用；旧占位文案不再出现在 UI。

## 5. 数据规范与算法口径

### 5.1 案例主表

沿用现有 Excel 23 列，并补充：

- `case_id`（CASE001）
- `cover_url`
- `summary`
- `display_allowed`
- `updated_at`
- `source_ids`

### 5.2 编码表

每个案例 10 行或 10 组字段：

```json
{
  "case_id": "CASE001",
  "indicator": "情感共通性",
  "score": 3,
  "evidence": "6条可核验评论中，多条明确出现‘感动/流泪/共鸣’……",
  "source_ids": ["C001-S001", "C001-S003"]
}
```

- `score` 允许 `null`，表示未知。
- `valid_count`、`mean_score` 由后端计算。
- `mean_score = sum(score) / valid_count`，保留两位小数。
- 缺失 ≥4 项时加 `low_coverage: true`。

### 5.3 音乐潜力

- 8 项评分，每项 0—100。
- 权重严格按老师给的比例。
- 总分 = Σ(分项 × 权重)。
- 等级按 80/65/50 分档。
- 必须附：推荐理由、文化兴趣点（音色/故事/意象/场景）、参考案例、适合区域、建议主题、改编建议、误读风险、来源。
- 任一项缺失：`score=null`、`tier='资料不足'`，不参与排序。

### 5.4 区域矩阵

- 一行 = 一个“区域 × 子受众 × 音乐 × 主题 × 城市”组合。
- 必填：区域、目标国家、受众、语言、文化背景、宗教/习俗注意、推荐音乐、主题、平台、形式、参考案例、改编建议、风险、来源、审核状态。
- 城市维度字段：`origin_city`（北京/上海/不限）、`city_anchor`（城市文化锚点）、`city_scene`（可用场景）、`city_narrative`（城市外宣叙事）、`city_sources`。
- 宗教/文化字段没有来源就不允许进入正式方案，只能标“待补来源”。
- 城市字段没有来源同样不进入正式方案。

### 5.5 方案输出

```json
{
  "meta": {
    "song": "春江花月夜",
    "region": "欧洲",
    "country": "德国",
    "audience": "音乐学院学生",
    "theme": "自然生态与山水审美",
    "language": "Deutsch",
    "format": "音乐会 + 工作坊",
    "generated_at": "2026-10-30T10:00:00+08:00",
    "generation_mode": "template",
    "ai_generated": false,
    "evidence_count": 2
  },
  "potential": { "score": 78, "tier": "适合传播，但需要适配", "reasons": [] },
  "cases": [],
  "success_factors": [],
  "narrative": { "one_liner": "", "pillars": [] },
  "platform_plan": {},
  "localization": {},
  "risks": [],
  "sources": [],
  "warnings": [],
  "disclaimer": "本方案由规则模板/大模型辅助生成，需人工审核；结论以案例库证据为准。"
}
```
